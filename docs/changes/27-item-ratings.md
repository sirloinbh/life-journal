# #27 완료한 항목에 평점과 세부 평점 매기기

- 이슈: [#27](https://github.com/sirloinbh/life-journal/issues/27)
- 브랜치: `feat/27-item-ratings`

## 목적

완료한 항목에 전체 평점과 분야별 세부 평점을 남긴다.

## 결정

이슈 댓글에 기록한 사용자 결정을 따른다.

- 5점 만점, 0.5점 단위.
- 세부 기준: 독서(내용·문장·여운), 영화·드라마(스토리·연출·연기), 공연(연기·연출·무대·음악), 주류(향·맛·여운·가성비), 여행(풍경·음식·숙소·교통).
- 전체 평점은 직접 매기고, 세부 평점 평균은 참고로만 보여 준다.

구현하면서 정한 값은 다음과 같다.

- 가장 낮은 점수는 0.5점이다.
- 전체 평점과 세부 평점은 모두 선택이다.
- 평점은 완료 항목에만 넣을 수 있다. 완료를 취소하면 평점도 함께 지워지고, 확인 창에 그 사실을 적었다.

## 변경 — 2026-10-31

- `database/migrations/003_item_ratings.sql`: `rating`, `sub_ratings` 컬럼. DB는 `rating`의 범위와 "완료 항목에만" 규칙을 `CHECK`로 막는다. `sub_ratings`는 객체 여부와 "완료 항목에만"만 DB가 막고, 키와 점수는 API가 검사한다.
- `backend/src/items.ts`: 평점 검증과 분야별 세부 기준, 저장·수정.
- `frontend/src/bucket-list.tsx`, `frontend/src/items.ts`: 완료 항목의 평점 버튼과 폼, 카드의 평점과 세부 평점·평균 표시, 완료 취소 시 평점 삭제.
- 별도 상세 화면이 없어 평점 입력은 카드에서 여는 대화 상자로 넣었다.

## 테스트

- `backend/test/items.test.ts`: 범위 밖 점수, 0.5 단위가 아닌 점수, 다른 분야의 기준, 완료 전 평점이 한국어 400으로 거절된다.
- `backend/test/db.integration.test.ts`: 마이그레이션 재적용, 평점 저장·유지·삭제, DB `CHECK`.
- `frontend/src/bucket-list.test.tsx`: 분야별 기준 표시, 평점 저장과 표시, 지우기, 거절 메시지.

## 검증 — 2026-10-31

임시 PostgreSQL 17.11을 `TEST_DATABASE_URL`로 지정해 Windows에서 실행했다.

## 1차 리뷰 반영 — 2026-10-31

head `63de36f`를 분리된 에이전트가 리뷰했다. 지적 4건(병합 차단 0, 보완 1, 사소함 3)은 모두 테스트 공백과 문서 표현이고, 동작 결함은 없었다. 모두 반영했다.

- 세부 기준 키를 서버와 화면 테스트의 표에 각각 적어, 한쪽 키가 바뀌면 그쪽 테스트가 실패하게 했다. 표는 두 곳에 있으므로 함께 고친다.
- 점수 경계 0.5·5의 수용과 세부 평점이 있는 항목의 분야 변경 테스트를 넣었다.
- 행이 있는 테이블에 마이그레이션을 적용하는 테스트를 임시 스키마로 넣었다. 잘못된 `CHECK`로 되돌려 이 테스트가 실패하는 것을 확인하고 코드를 되돌렸다.
- `CHECK` 설명을 실제 범위에 맞게 고쳤다.

리뷰에서 동작을 확인했지만 고치지 않은 것: 저장 요청 중에는 Select가 비활성화되지 않아 그때 바꾼 값은 저장되지 않는다. 기존 폼도 같고 요청이 진행되는 짧은 시간에만 생긴다.
