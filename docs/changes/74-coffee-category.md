# #74 새 분야 커피 추가하기

- 이슈: [#74](https://github.com/sirloinbh/life-journal/issues/74)
- 브랜치: `feat/74-coffee-category`

## 변경 — 2026-11-03

버킷리스트에 여섯 번째 분야 "커피"를 더했다. 항목을 추가하고, 완료하고, 평점과 감상문을 남길 수 있다. 착수 전 결정은 [이슈 댓글](https://github.com/sirloinbh/life-journal/issues/74#issuecomment-6606545493)에 있다.

- 분야: 주류와 별도의 새 분야 `coffee`. 세부 종류는 없다.
- 세부 정보: 로스터리(`roastery`), 원산지(`origin`), 추출 방식(`brewMethod`). 모두 선택이고 자유 입력이다. 카드 추천안에 사용자가 추출 방식을 더했다.
- 세부 평점: 향(`aroma`), 산미(`acidity`), 단맛(`sweetness`), 바디(`body`), 여운(`finish`).
- DB: 마이그레이션 `007_coffee_category.sql`이 `items_category_check` 제약을 지우고 `coffee`를 더한 제약으로 다시 만든다. 이름으로 지우고 다시 만들어 재실행해도 안전하다. 한 트랜잭션으로 묶었다.
- 백엔드: `backend/src/items.ts`에 분야 목록 `CATEGORY_KEYS`를 두고, 분야 검증·목록 필터·분야 정렬이 이 목록을 함께 쓰게 했다. 전에는 같은 배열이 세 곳에 따로 적혀 있었다. `CATEGORIES` 객체의 키는 여전히 따로 적지만, `satisfies`로 `CATEGORY_KEYS`와 맞지 않으면 타입 오류가 난다.
- 프런트엔드: `frontend/src/items.ts`의 분야 정의에 커피를 더했다. 탭, 항목 폼, 평점 폼, 표 보기 분야 필터가 이 정의를 따른다.
- OpenAPI: 저장소에 OpenAPI 문서가 아직 없다(`docs/project-setup.md`에서 외부 클라이언트가 생길 때 만들기로 했다). 그래서 갱신하지 않았다.
- 기존 로컬 DB에는 `database/README.md`의 방법으로 `007`을 적용해야 한다. `docs/next-steps/README.md`의 안내를 `002`~`007`로 고쳤다.

## 테스트

- `backend/test/items.test.ts`: 커피에 없는 세부 정보, 세부 종류, 문자가 아닌 세부 정보 값, 커피에 없는 세부 평점이 한국어 400으로 거절된다. 커피의 세부 평점 5개와 점수 양 끝이 받아들여진다.
- `backend/test/db.integration.test.ts`
  - 6개 분야 항목을 실제 DB에 만들고 읽는다. 커피는 세부 정보 3개, 전체 평점, 세부 평점 5개를 담아 완료 상태로 만든다.
  - 기존 항목이 있는 테이블에 `007`을 두 번 적용해도 오류가 없다. 적용 전에는 커피가 거절되고, 적용 뒤에는 저장되며, 모르는 분야는 여전히 거절된다. 기존 행은 그대로다.
  - 재실행 테스트 목록에 `007`을 더했다.
  - 이 테스트는 연결 하나를 직접 잡아 쓴다. `pool.query`는 오류가 난 연결을 버려서 `search_path` 설정이 사라지기 때문이다.
- `frontend/src/bucket-list.test.tsx`: 커피 탭에서 항목을 추가, 수정, 완료, 완료 취소, 삭제한다. 평점 폼에 세부 평점 5개가 나오고 보내진다.
- `frontend/src/items-table.test.tsx`: 표 보기 분야 필터에서 커피를 고르면 `category=coffee`로 다시 묻고, 행에 "커피"가 보인다.

- 브라우저: 실제 API, Vite, 테스트 DB를 띄우고 헤드리스 Chrome 156을 DevTools 프로토콜로 조작했다. 모바일 390×844(터치 없는 모바일 에뮬레이션)와 PC 1440×900에서 모두 통과했다.
  - 첫 화면에서 커피 탭으로 이동, 항목 추가(세부 정보 3개), 새로고침 뒤 유지, 완료 표시, 전체 평점과 세부 평점 5개 저장, 표 보기 커피 필터, 삭제
  - 목록과 표 보기 모두 페이지가 가로로 넘치지 않았다. 모바일에서도 탭 6개가 한 줄에 들어갔다.

  - 항목 폼, 평점 폼, 목록, 표 보기 캡처를 눈으로 확인했다. 임시 파일이라 저장소에는 넣지 않았다.
